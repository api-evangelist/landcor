# Landcor Data

> Landcor Data Corporation is a New Westminster, British Columbia property data and automated valuation company, founded in 2000, that sells residential valuations, assessment detail and land title documents across roughly 1.9 million BC residential properties. It sits in the valuation and public-record layer of the Canadian real estate value chain, not the listings layer: inputs are BC Assessment, the Land Title and Survey Authority (LTSA), BC Registry Services, municipal tax certificates and ICIS-licensed cadastral material; outputs are the Property Valuator (AVM), Adjusted Value Profiler, Property Profiler, Title Search Plus and historic valuation reports sold to lenders, appraisers, notaries, insurers and brokerages.

Access reality, stated up front so an agent does not waste calls: Landcor runs a live, anonymously readable OpenAPI 3.1.0 contract at https://api.landcor.com/openapi.json with Swagger UI at /docs and ReDoc at /redoc, but publishes NO developer portal, NO key-issuance page, NO API pricing and NO API terms. Every operation except GET /health returns HTTP 401 {"detail":"Missing token"}. Tokens are obtained only through a direct commercial arrangement (1-866-LANDCOR or https://www.landcor.com/contact/). The contract is open; the access is closed.

## APIs

- [Landcor Property API](https://api.landcor.com/docs): Twelve REST operations over BC residential property data — search, detail, PDF report, address autocomplete, AVM valuation range/history/LTV check, neighbourhood sales series, comparables and AVM narrative summary. Base URL https://api.landcor.com. Auth: HTTP Bearer, no public issuance route.

## Operations

- `GET /health` — health_check_health_get — liveness; the only unauthenticated operation.
- `GET /property/search` — search_property_property_search_get — address filters: unit_number, street_direction, street_number, street_name, postal_code. All optional. Unbounded array response.
- `GET /property/{pid}` — read_property_property__pid__get — full property detail. pid matches ^\d{3}-\d{3}-\d{3}$.
- `GET /property/{pid}/report/pdf` — read_property_pdf_property__pid__report_pdf_get — base64-encoded, password-protected PDF inside a JSON envelope.
- `GET /address/autocomplete` — autocomplete_address_address_autocomplete_get — q (3..200 chars, required), limit (1..50).
- `GET /valuationRange/{pid}` — read_valuation_range_valuationRange__pid__get — current AVM low/high band.
- `GET /valuationRange/{pid}/updates` — read_property_monthly_update_valuationRange__pid__updates_get — legacy alias; the spec says it now mirrors the valuation range endpoint. Prefer the endpoint above.
- `GET /valuationRange/{pid}/history` — read_valuation_history_valuationRange__pid__history_get — chronological snapshots.
- `POST /valuation/ltv-check` — run_ltv_check_valuation_ltv_check_post — body {pid, ltv_amount}; returns has_avm and avm_exceeds_ltv. Creates nothing.
- `GET /valuation/neighbourhood/{neighbourhood_code}/{unit_type_code}/sales` — read_neighbourhood_sales_series_valuation_neighbourhood__neighbourhood_code___unit_type_code__sales_get — interval monthly|rolling3m, months, snapshot_day. Codes come from a prior property detail call.
- `GET /comparables/{pid}` — read_comparables_comparables__pid__get — comparable properties with distance to subject.
- `POST /generate-avm-summary` — generate_avm_summary_generate_avm_summary_post — caller supplies the AVM payload; the service returns a narrative summary plus a validation result.

## Conventions

- Identifier: the Landcor PID, `xxx-xxx-xxx`. Not the RESO Universal Property Identifier. Landcor holds no RESO certification and is not a RESO member.
- Auth: `Authorization: Bearer <token>` on everything except `/health`.
- Errors: FastAPI `{"detail": ...}` — a string for 401/404/502, an array of `{loc, msg, type}` for 422. Not RFC 9457.
- No idempotency contract, no pagination, no request-id header, no API version in the path, no rate-limit headers. Volume is governed contractually by the Acceptable Use policy ("not to stockpile data pulls").
- No webhooks, no events, no AsyncAPI, no GraphQL, no gRPC, no SDKs on any public registry, no CLI, no sandbox, no changelog, no status page.
